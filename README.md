# Последний рубеж — веб-версия настольной игры «Бункер»

Локальная браузерная игра для компании друзей с отдельными игровыми комнатами, ведущим, наблюдателями, публичным голосованием и пользовательскими паками характеристик. **Код и базовый контент — оригинальные.** Названия категорий ориентированы на знакомую игру; содержимое карт не скопировано с чужого сайта.

Стек: **React 19 + TypeScript + Vite / FastAPI + SQLAlchemy + Alembic / PostgreSQL 16 / WebSocket / Docker Compose + nginx**.

## Быстрый запуск на Windows (Docker Desktop)

Откройте PowerShell в папке проекта:

```powershell
Copy-Item .env.example .env
notepad .env
```

Установите в `.env` собственные надёжные `ADMIN_PASSWORD` и `POSTGRES_PASSWORD` (не используйте значения из примера). Затем:

```powershell
docker compose up -d --build
```

Откройте **http://localhost:8080** на компьютере, где запущен Docker. Готово: создайте комнату и отправьте ссылку друзьям.

Проверка работоспособности API: **http://localhost:8080/api/health**.

При первом запуске PostgreSQL создаётся в именованном томе, Alembic автоматически применяет начальную миграцию, сервер добавляет базовый пак. При последующих обновлениях встроенный базовый пак обновляется по его ревизии; снимки уже созданных комнат не затрагиваются. Следующие запуски не удаляют комнаты и паки.

### Игра по Radmin VPN

1. Все игроки подключаются к одной сети Radmin VPN.
2. Владелец сервера узнаёт свой **Radmin IPv4-адрес** (например, `26.123.45.67`).
3. Друзья открывают **http://26.123.45.67:8080**. Список комнат и ссылки работают через этот адрес.
4. Если страница не открывается, разрешите входящие TCP-подключения на порт **8080** в брандмауэре Windows **для сетевого интерфейса/подсети Radmin**. Проверяйте, что Docker Desktop запущен.
5. Голосовое общение остаётся в Discord; веб-приложению микрофон не нужен.

В `docker-compose.yml` nginx слушает `0.0.0.0:${PORT:-8080}`, а **API и PostgreSQL не публикуют порты на хост**. Порт меняется через `PORT` в `.env`.

**При обновлении с v0.1/v0.2/v0.3:** распакуйте новую версию поверх исходников и выполните `docker compose up -d --build`. PostgreSQL сохранит ваши комнаты и созданные паки; **не выполняйте `docker compose down -v`**. Новые правила раскрытия работают и для существующих комнат; миграции БД не нужны.

**Важно:** обычный HTTP не шифрует трафик. Приложение рассчитано на *доверенную локальную/VPN-сеть*. Не пробрасывайте порт на открытый интернет без HTTPS, аутентификации и дополнительного hardening. У игроков нет полноценных аккаунтов: токен комнаты хранится в `localStorage` их браузера. Повторный вход с того же браузера возвращает их роль; смена браузера/очистка данных без токена — новая сессия. Пароль администратора хранится в `.env` сервера и в памяти сессии браузера при работе редактора.

## Изменения в v0.6 — стаж, бонусы и навыки

- **У профессий и хобби появилось случайное звание опыта.** Для профессий базовая шкала: Новичок (до 3 мес.), Стажёр (3 мес. — 1 год), Любитель (1–2 года), Опытный (2–5 лет), Профессионал (5–10 лет), Эксперт (более 10 лет). Для хобби: Новичок (до 3 мес.), Любитель (3 мес. — 1 год), Опытный (1–2 года), Продвинутый (2–5 лет), Мастер (гуру) (более 5 лет). Рядом с картой сразу видны название и длительность уровня, а над сценарием есть разворачиваемая справка по обеим шкалам. Для базовых профессий опыт не может требовать больше лет, чем допускает примерный возраст персонажа (карьера считается с 16 лет). Ориентир по шкалам: [вики профессий](https://bunker-online.com/ru/wiki/profession), [вики хобби](https://bunker-online.com/ru/wiki/hobby).
- **Оригинальные нарративные плюсы** для всех 20 профессий и 15 хобби базового пака: от починки генераторов и выращивания рассады до организации эвакуации и полезных находок. Пассивное описание видно всем **только после раскрытия** соответствующей карты; до него бонус не отсылается другим пользователям.
- **Три активных навыка** (помимо двух спецвозможностей игрока):
  - `medical_aid` — применяющий выбирает активного игрока и его **открытую карту здоровья**. К ней добавляется публичная отметка «Помощь оказал…». Диагноз остаётся в силе: это стабилизация/помощь, а не магическое исцеление. Нельзя лечить скрытую карту, уже обработанную карту или явно здоровое состояние.
  - `find_item` — выбирается предметная категория (`inventory: true`), система выдаёт **новую уникальную раскрытую вещь** из неё в личный инвентарь применяющего. Новая карта появляется в общей таблице.
  - `discover_cache` — поиск случайной новой находки из `bunker.equipment`, которая появляется в **общем оснащении бункера** под заголовком «Найденные тайники». Без расхода способности, если нет новых вариантов.
- **Раскрытие ≠ использование навыка:** профессиональный/хобби-навык можно применить позже, только во время активной игры, отдельной кнопкой на **уже открытой** карте. По умолчанию навык одноразовый на карту. Ведущий также может применить его от имени выбранного игрока через «Управление партией → Навык профессии / хобби», если карта уже открыта; ошибка не расходует навык. Ведущий может отменить результат одним откатом. Раскрытие двух специальных возможностей, как прежде, активирует их сразу.
- **Редактор паков:** для каждой категории можно включить шкалу стажа («Профессия», «Хобби», «Без стажа»), настроить собственные названия и сроки и отметить категорию здоровья (`medical: true`). Преимущества и навыки задаются в редакторе карточек или в JSON. Старые паки продолжают работать: для `job` и `hobby` без поля `experience` включены их классические шкалы, остальные категории без стажа.
- **Обновление встроенного базового пака до ревизии 6** происходит при следующем запуске сервера. Прежние комнаты и кастомные паки не переписываются. **Миграция базы не нужна.**

### Формат одной карточки с бонусом

В визуальном редакторе строка:

```text
Полевой врач || Оказывает медицинскую помощь в сложных условиях || medical_aid
Геолог || Определяет опасные породы и находит хранилища || discover_cache
Мастерская кулинария || Может прокормить команду из скромных запасов
```

Эквивалентный JSON:

```json
{
  "id": "role", "name": "Специализация", "experience": "profession",
  "items": [
    {"text": "Полевой врач", "bonus": "Оказывает медицинскую помощь", "skill": "medical_aid"},
    {"text": "Геолог", "bonus": "Может найти скрытые запасы", "skill": "discover_cache"},
    {"text": "Повар", "bonus": "Умеет экономить провизию"}
  ],
  "experience_levels": [
    {"name": "Новичок", "duration": "до 3 месяцев"},
    {"name": "Следопыт", "duration": "более 2 лет", "min_age": 18}
  ]
}
```

Для лекарства/лечения используйте категорию с `"medical": true`, для находок в инвентаре — `"inventory": true`. Для общего тайника в паке должно быть поле `bunker.equipment` (список вариантов оборудования). Длительности стажа являются описательными строками, не таймерами.

## Изменения в v0.5

- **Ручные способности ведущего**: теперь тип эффекта и участники выбираются в одном окне. Кому добавить карту, чью характеристику заменить, какие **два разных игрока** участвуют в краже или обмене — задаётся явно. Ведущий больше не подставляется получателем по умолчанию. Действие выполняется на сервере от имени выбранного участника.
- **Две спецвозможности в базовом паке**: каждый игрок получает две карты категории «Спец. возможность» вместо одной. При раздаче система старается не выдавать повторные значения одному игроку, если вариантов хватает.
- **Кража (`steal`) ограничена предметами**: доступно только то, что уже раскрыто в категориях инвентаря. Отдельно выбираются владелец → категория («Рюкзак», «Крупный инвентарь» и пользовательские) → конкретный предмет. Закрытые характеристики не показываются, выбора случайной закрытой карты нет даже для ведущего. Профессию или черту характера украсть нельзя.
- **Предмет после кражи остаётся открытым** и отображается в общей таблице у нового владельца. Откат ведущего возвращает предмет на место.
- **Произвольные паки** могут добавлять свои инвентарные категории через флажок «Предметы (доступны для кражи)» в редакторе. В JSON это `"inventory": true`. Старые паки без этого поля по-прежнему распознают базовые `large` и `bag`; для других категорий признак указывается явно.
- **Встроенный пак обновлён до ревизии 5**: применится автоматически при запуске на старой базе, но только для вновь созданных комнат. Старые комнаты используют сохранённый снимок паков; структура базы не меняется.

## Изменения в v0.4

- **Новый визуальный стиль**: интерфейс оформлен под постапокалипсис — более тёплая палитра, ржаво-песочные акценты, затемнённые панели и более выраженные игровые секции.
- **Катастрофа стала информативнее**: в блоке сценария показываются не только базовое описание события, но и секции «Первые последствия» и «Что особенно важно». Для встроенного пака тексты самих катастроф тоже расширены.
- **Бункер выглядит богаче**: места в убежище вынесены в отдельный акцентный блок, а состав бункера может включать несколько пунктов внутри одного параметра (например, провизию, оборудование, защиту, медицину и особые условия).
- **Встроенный базовый пак обновлён до revision 4** и автоматически переобновляется при запуске сервера, если в базе всё ещё лежит старая встроенная версия. Это влияет только на новые комнаты; уже начатые партии используют свой сохранённый snapshot, как и раньше.
- **Матрица раскрытий уплотнена**: текст в ячейках принудительно переносится, таблица использует фиксированную ширину колонок и старается помещаться в экран без постоянного горизонтального скролла.

## Изменения в v0.3

- **Раскрытие после исключения и финала**: каждый участник может открыть свои оставшиеся карты даже после выбывания или завершения партии. Это публичное раскрытие для просмотра; **спецэффекты в этих случаях не применяются**, чтобы не менять уже сыгранный результат. Ведущий по-прежнему может раскрывать карты за других участников через API.
- **Таблица переставлена местами**: теперь **строки = игроки**, **столбцы = категории характеристик**. Несколько раскрытий одной категории отображаются в одной ячейке, включая добавленные картой `add_random`.
- **Полноширинная компоновка**: катастрофа, убежище, ход игры, личные карты, голосование, управление ведущего, список игроков и таблица идут самостоятельными секциями во всю ширину рабочей области, вместо узкого бокового столбца.
- **Навигация по якорям** над игрой: сценарий, текущий ход, голосование, личные карты, ведущий, общая таблица и игроки. При старте новой партии, смене раунда или выступающего, начале/повторном туре голосования и завершении происходит плавный переход к соответствующей секции. Обычные обновления по WebSocket и раскрытия карт прокрутку не трогают.

Сохранены предыдущие изменения v0.2: `add_random` избегает дублирования собственных карт, спецэффекты срабатывают вместе с раскрытием **во время активной игры**, раунды/лимиты раскрытия необязательны, есть откат и редактор паков.

## Что реализовано

- **Лобби**: публичный список комнат, создание по названию, ссылка-приглашение, вход по никнейму, роль зрителя, до 2 одновременно активных комнат по умолчанию (`MAX_ROOMS`). Минимум 2 игрока для тестовой партии, технический лимит 30; **рекомендуем 6–15**.
- **Ведущий участвует в партии**: может удалить лишнего участника в лобби, запускает её, переключает выступающих и раунды, открывает и завершает голосование, ставит/снимает паузу, вручную исключает и возвращает игрока, применяет специальные эффекты и откатывает последние **35 игровых действий**.
- **Раунды (необязательно)**: ведущий может переключать раунды без ограничений по количеству; каждый следующий циклически смещает первого выступающего на одну исходную позицию. Выбывшие пропускаются. Можно оставаться в первом раунде всю игру и раскрывать карты свободно. Таймеры настраиваются, их истечение **не запускает следующий ход**.
- **Раскрытие**: в любом порядке, сколько угодно карт в любой раунд. Обязательная первая категория и лимиты раскрытия больше не применяются, **в том числе в старых комнатах и паках**. Исключённый игрок и участник завершённой партии **могут продолжать открывать карты**, но их спецэффекты не срабатывают; новые раскрытия видны всем в таблице.
- **Голосование**: один голос каждого активного игрока; голос можно изменить до завершения. Есть **«Пропустить»** (большинство активных голосов), второй тур при ничьей, ручное разрешение повторной ничьей ведущим. Решения не раскрываются другим до подсчёта: сервер отправляет только статус участия и собственный выбор. Голосование можно запускать снова в том же раунде.
- **Спецвозможности**: **«Раскрыть и применить»** — одно действие. Если нужны параметры, например категория новой карты или цель обмена, окно выбора появляется *перед* раскрытием; подтверждение атомарно раскрывает и исполняет способность. Ведущий может выполнить и откатить действия вручную. Для чужой закрытой карты сервер выбирает случайную, не раскрывая её посторонним. Старый вызов `ability` оставлен для совместимости с уже раскрытыми, но ещё не использованными картами из старых комнат; отдельной кнопки больше нет.
- **Секретность**: сервер возвращает полноценную руку только её владельцу. Для остальных отправляет только раскрытые карты. Никаких секретных рук в общих WebSocket-сообщениях.
- **Добавление случайной карты**: `add_random` не повторяет уже имеющийся у игрока **текст карты той же категории**, включая закрытые карты. Если все варианты исчерпаны, действие отклоняется без раскрытия спецкарты; при отмене эффект и раскрытие откатываются вместе. Между *разными* игроками совпадения по-прежнему допустимы.
- **Матрица раскрытий**: под игровым экраном общая таблица с переносами текста в ячейках. **Строки = игроки, столбцы = категории**; несколько раскрытых карт одной категории находятся **в одной ячейке**. Закрытые карты никому не показываются.
- **Генератор сценария**: случайная катастрофа, независимо случайные значения местоположения, площади, срока, еды и оборудования; состав параметров изменяется в паке. Места рассчитываются из числа стартовавших (по умолчанию `floor(N × 0.5)`).
- **Версии паков**: при создании комнаты она получает независимый снимок JSON. Редактирование пака не изменяет уже существующую комнату, даже если партия ещё не началась.
- **Администрирование**: пароль из `.env` для создания/изменения/удаления паков и удаления комнат через редактор; доступ к API документации `/docs`.

## Редактор паков

Кнопка **«Управление паками»** на главной → пароль `ADMIN_PASSWORD`. Визуальный редактор позволяет создавать, отключать, удалять и **переставлять категории**, отмечать предметные категории флажком «Предметы (доступны для кражи)»; добавлять варианты карт; менять число карт категории на человека; менять катастрофы и динамические поля бункера; задавать правила. Поддерживается **импорт и экспорт JSON**, а также сохранение своего пака/его копии. Встроенный базовый пак не перезаписывается, но его можно скопировать и изменить.

Фрагмент формата:

```json
{
  "title": "Ночной рейд",
  "categories": [
    {"id": "role", "name": "Специализация", "enabled": true, "draw_count": 1, "items": ["Разведчик", "Медик", "Инженер"]},
    {"id": "artifact", "name": "Артефакт", "enabled": true, "inventory": true, "items": ["Компас", "Талисман"]},
    {"id": "power", "name": "Особое действие", "draw_count": 2, "items": [{"text": "Забери раскрытый предмет", "effect": "steal"}, {"text": "Ещё одна карта", "effect": "add_random"}]}
  ],
  "catastrophes": ["Катастрофа изменила привычный мир."],
  "bunker": {
    "location": ["Подземный пункт", "Старая станция"],
    "area": ["50 м²", "180 м²"],
    "food": ["Провизии на 3 месяца", "Провизии на 2 года"]
  },
  "settings": {
    "max_rounds": 0,
    "speech_seconds": 60,
    "vote_seconds": 60,
    "bunker_fraction": 0.5,
    "reveal_limit": -1,
    "first_required_category": ""
  }
}
```

Поддерживаемые `effect`: `add_random`, `reroll`, `swap`, `steal`, `revive`. Поля `max_rounds`, `reveal_limit` и `first_required_category` сохранены в JSON для обратной совместимости, но теперь **не ограничивают игру**; визуальный редактор их не предлагает. В настройках комнаты используются только таймеры. Визуальный редактор понимает строки вида `Забери чужую карту => steal` и превращает их в JSON-объекты с эффектами.

## Как устроен проект

```text
bunker-project/
├── .env.example            # конфигурация хоста
├── docker-compose.yml      # nginx + FastAPI + PostgreSQL
├── .github/workflows/ci.yml
├── frontend/
│   ├── Dockerfile
│   ├── nginx.conf           # SPA + reverse proxy REST/WS
│   ├── src/main.tsx        # лобби, игра, ведущий, редактор
│   └── src/style.css
└── backend/
    ├── Dockerfile
    ├── requirements.txt
    ├── alembic.ini
    ├── migrations/versions/0001_initial.py
    ├── tests/test_api.py
    └── app/
        ├── db.py           # ORM Pack/Room/Player
        ├── seed.py         # оригинальный стартовый контент
        ├── game.py         # правила и приватные DTO
        └── main.py         # HTTP API + WebSocket
```

**БД:** `packs` (версии контента), `rooms` (конфигурация, snapshot пака, состояние партии, undo), `players` (токен, рука, выбывание, роли). `rooms.state` — JSON состояния игровой машины. Это сознательное решение для компактного проекта на 2 комнаты; для большого SaaS понадобятся распределённые WS, более строгая модель событий и масштабирование.

**WebSocket:** сообщение `sync` уведомляет клиентов об изменении состояния; каждый клиент загружает **своё** приватно-фильтрованное состояние по HTTP. Сокет аутентифицируется первым JSON-сообщением `{"token":"..."}`, токен не добавляется в URL. При потере соединения сокет переподключается, дополнительно есть редкая HTTP-проверка.

## Запуск для разработки без Docker

**Backend (Python 3.12+):**

```bash
cd backend
python -m venv .venv
# активируйте виртуальную среду (Windows: .venv\Scripts\activate)
pip install -r requirements-dev.txt
# По умолчанию применяется SQLite ./bunker-dev.db, если DATABASE_URL не установлен
alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

**Frontend (Node.js 22+):**

```bash
cd frontend
npm install
npm run dev
```

Откройте **http://localhost:5173**. В режиме разработки Vite проксирует `/api` и `/ws` в FastAPI на порту 8000. Для защиты административных операций в локальном окружении задайте `ADMIN_PASSWORD` в переменных среды **до запуска backend**.

## Границы этой версии

Это **играбельный MVP для частной компании**, а не публичная production-платформа. Правила оригинального ресурса весьма детализированы: здесь реализована собственная управляемая ведущим версия с двумя турами ничьей, пропуском и базовыми эффектами, **без автоматических оправдательных речей, 70%-порога исключения, принудительного двойного голосования после пропуска и сценариев произвольного исполняемого кода в паках**. Неразрешённые повторные ничьи решает ведущий вручную. Способности в кастомных паках ограничены пятью безопасными встроенными типами; для новых механик нужен обработчик на бэкенде.

В версии для друзей нет регистрации, голосового чата, статистики партий и адаптивной мобильной версии — по первоначальным требованиям.
