# Контракт программного интерфейса: голосование

**Лабораторная работа № 3** · Версия контракта 1.0 · 10.11.2026  
**Проект:** «Последний рубеж» (Bunker Online, MVP 0.6.0)  
**Связь с требованиями:** [FR-5 и US-5](01-requirements.md#us-5--голосование-fr-5) из лабораторной № 2.

## 1. Выбор операции

**Назначение:** активный игрок отдаёт голос за другого активного игрока или за пропуск исключения, либо меняет свой голос до подсчёта.

**Вызывающая сторона:** браузерный клиент React от имени участника комнаты. Вызов доступен также другому HTTP-клиенту, если у него есть действительный токен участника.

**Реализация:**
- [Маршрут FastAPI `vote`](../backend/app/main.py) — `@app.post('/api/rooms/{room_id}/vote')`.
- [Модель `VoteRequest` и функция `cast_vote`](../backend/app/game.py) — валидация хода и запись голоса.
- Существующие [серверные тесты](../backend/tests/test_api.py), в частности `test_skip_and_tie_runoff`.

## 2. Контракт HTTP

| Поле | Значение |
|---|---|
| Метод | `POST` |
| Путь | `/api/rooms/{room_id}/vote` |
| `room_id` (path) | Строка; существующий код комнаты (создаваемый сервером, шесть шестнадцатеричных символов в верхнем регистре) |
| `X-Player-Token` (header) | Обязательная непустая строка; непрозрачный токен игрока, полученный при создании комнаты или входе |
| `Content-Type` (header) | `application/json` |
| `target` (JSON body) | Обязательная строка длиной **1–40 символов**: `"skip"` либо `player_id` другого/своего активного игрока данной комнаты |
| Условие вызова | Комната существует и находится в фазе `voting`; токен действителен; игрок активен (не зритель и не исключён); `target` доступен, а при повторном туре принадлежит списку финалистов |
| Успешный ответ | HTTP **200**, JSON `{"ok":true}` |
| Побочный эффект | Сервер записывает `state.votes[player_id] = target` (повторный вызов заменяет прежний голос), фиксирует транзакцию и отправляет уведомление WebSocket `{"type":"sync"}` |
| Как увидеть эффект | `GET /api/rooms/{room_id}` с собственным токеном: `state.my_vote` содержит выбор; `state.vote_count` увеличивается при первом голосе, но не при замене; чужой `my_vote` недоступен |

### Ошибки и ограничения

| Код | Когда | Ответ |
|---|---|---|
| **400** | Голос до открытия голосования, после него, от зрителя или исключённого игрока | `{"detail":"Голосовать сейчас нельзя"}` |
| **400** | Указан выбывший или зритель как цель | `{"detail":"Нельзя голосовать за этого игрока"}` |
| **400** | Во втором туре цель не из списка финалистов | `{"detail":"Второй тур: выбирайте финалиста"}` |
| **401** | Нет токена или он не принадлежит комнате | `{"detail":"Войдите в комнату"}` или `{"detail":"Неизвестный токен игрока"}` |
| **404** | Комната не найдена | `{"detail":"Комната не найдена"}` |
| **422** | Тело не соответствует схеме (например, `target` отсутствует или пуст) | Стандартный JSON-ответ FastAPI с `detail` — перечнем ошибок валидации |

**Примечания:** `X-Player-Token` — секрет доступа к одному участнику; его нельзя добавлять в URL, публиковать в репозитории или передавать другим игрокам. Адрес сервера в локальном развёртывании: `http://localhost:8080`. Публичный Интернет/HTTPS текущим MVP не заявлены.

## 3. Подготовка тестовой комнаты

Оба примера ниже используют **иллюстративные значения** `room_id="A1B2C3"` и `X-Player-Token: demo-player-token`. В реальной игре их нужно заменить значениями, выданными API, иначе получите 404/401. Чтобы подготовить реальную комнату:

1. `POST /api/rooms` с JSON `{"title":"Тестовая партия","nickname":"Ведущий","pack_id":"basic","config":{}}`. Запомнить возвращённые `id` и `token` ведущего.
2. `POST /api/rooms/{id}/join` с `{"nickname":"Алиса","spectator":false}`. Запомнить `token` Алисы.
3. `POST /api/rooms/{id}/command` с токеном ведущего и `{"type":"start","data":{}}`. Комната перейдёт в `round`.
4. Для **ошибочного** примера выполнить голосование сейчас; для **успешного** сперва открыть его командой ведущего `{"type":"open_vote","data":{}}`.

Тело ошибки и успешного ответа ниже — точные значения; выданные сервером коды и токены в каждом запуске случайны.

## 4. Два конкретных примера

### Пример А — успешное голосование за пропуск (HTTP 200)

**Предусловие:** тестовая комната `A1B2C3` в фазе `voting`, `demo-player-token` является действительным токеном активной Алисы. Ведущий предварительно вызвал `open_vote`.

```http
POST /api/rooms/A1B2C3/vote HTTP/1.1
Host: localhost:8080
Content-Type: application/json
X-Player-Token: demo-player-token

{"target":"skip"}
```

Ожидаемый ответ:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"ok":true}
```

Ожидаемое состояние при последующем `GET /api/rooms/A1B2C3` от имени Алисы: `state.my_vote="skip"`, `state.vote_count=1` (если остальные ещё не голосовали). При запросе от другого участника `state.my_vote=null`; полный словарь `votes` не выдаётся. Если Алиса меняет выбор на идентификатор активного игрока, счётчик голосов останется 1.

### Пример Б — голосование до начала фазы (HTTP 400)

**Предусловие:** та же комната и активный игрок, но ведущий запустил игру и ещё не вызвал `open_vote`; текущая фаза `round`.

```http
POST /api/rooms/A1B2C3/vote HTTP/1.1
Host: localhost:8080
Content-Type: application/json
X-Player-Token: demo-player-token

{"target":"skip"}
```

Ожидаемый ответ:

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{"detail":"Голосовать сейчас нельзя"}
```

**Ожидаемый эффект:** голос **не сохраняется**; у Алисы `state.my_vote=null`, `state.vote_count=0` (если голосов до вызова не было). Комната остаётся в фазе `round`.

## 5. Проверка контракта и ревью

- **Сценарий:** US-5 ↔ FR-5; успешный и ошибочный примеры используются как основа автоматических тестов лабораторной № 4.
- **Ручная проверка:** создать две сессии игроков, пройти шаги выше, проверить HTTP-статусы, JSON и отсутствие утечки чужого голоса.
- **Ревью:** другой участник команды (или другой студент при индивидуальной работе) должен составить запрос и ожидаемый ответ *самостоятельно по этому документу*, оставить содержательный комментарий в PR. Автор уточняет контракт при необходимости. До действительного ревью и merge лабораторная не считается завершённой.
