# ADR-0001: WebSocket уведомляет о смене состояния, REST выдаёт приватное представление

**Статус:** реализовано в исходной версии. **Дата фиксации:** 2026-11-10.

## Контекст
Игрок видит свои закрытые карты и выбор голоса; другие участники не должны получать секретные данные даже через сетевые сообщения. Требуется синхронизация партии между браузерами.

## Решение
WebSocket `/ws/rooms/{room_id}` принимает токен в первом JSON-сообщении и затем отправляет только `{"type":"sync"}`. После уведомления браузер запрашивает `GET /api/rooms/{id}` со своим `X-Player-Token`, а `public_state` формирует персонализированный ответ.

## Последствия
+ Не возникает общей WebSocket-рассылки с приватными картами.
+ HTTP-ответ проще тестировать и кешировать по авторизации нельзя.
− После изменения нужен дополнительный HTTP-запрос от каждого клиента.
− Для масштабирования на несколько backend-процессов потребуется общий брокер уведомлений.
